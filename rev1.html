Overview

Given a compiled x86 32-bit ELF binary with no source code, the goal was to reverse engineer the password validation logic and produce a working keygen — a program that generates an arbitrary number of valid keys independently.

This is a foundational reverse engineering task that mirrors real-world scenarios: cracking license checks, reversing authentication schemes, and understanding proprietary protocol validation — all common in malware analysis and vulnerability research.

Decoding Compiler Optimized Division

The most interesting RE challenge in this binary was recognizing compiler-optimized modulo. Modern compilers never emit a slow div instruction for modulo by a constant — instead they use a magic multiplier trick. Two instances appeared:

IDA — modulo 7 check
; (a * b) % 7 == 3
mov     eax, [ebp+i_0]
imul    eax, [ebp+i_2]       ; eax = a * b
mov     ecx, eax
mov     edx, 92492493h      ; ← magic constant for ÷7
imul    edx
; ... arithmetic normalization ...
cmp     eax, 3             ; remainder must be 3
jz      short loc_8049263
IDA — modulo 5 check
; (b + c) % 5 == 1
lea     ecx, [edx+eax]        ; ecx = b + c
mov     edx, 66666667h      ; ← magic constant for ÷5
imul    edx
; ... arithmetic normalization ...
cmp     edx, 1             ; remainder must be 1
jz      short loc_8049295
⚡ Pattern to Memorize
Magic constant 92492493h = compiler doing % 7  |  66666667h = compiler doing % 5. These appear constantly in real-world RE — license checks, hash functions, protocol parsers.

Phase 3 — Writing the Keygen

With all constraints mapped, a brute-force keygen over the constrained search space produces valid keys in milliseconds:

Python — keygen
from pwn import *

valid_keys = []

for a in range(0, 26):       # key[0]: A–Z
    for b in range(0, 10):    # key[2]: 0–9
        for c in range(0, 10): # key[5]: 0–9
            if (a * b) % 7 == 3 and (b + c) % 5 == 1:
                k0 = chr(a + ord('A'))
                k2 = chr(b + ord('0'))
                k5 = chr(c + ord('0'))
                k3 = 'X'          # unconstrained position
                k6 = k3
                k7 = chr(ord(k0) + 1)
                key = f"{k0}-{k2}{k3}-{k5}{k6}{k7}"
                valid_keys.append(key)

for k in valid_keys[:10]:
    print(k)

What I Learned

01 — Triage First

Running file, strings, nm, and readelf before touching IDA builds a hypothesis in under 60 seconds. Architecture, strip status, and imported functions tell you what you're dealing with before reading a single instruction.

02 — Reading Index Arithmetic

The pattern add eax, N followed by movzx eax, byte ptr [eax] is how compilers emit array indexing. Recognizing N as the array index lets you map disassembly back to source-level structure without symbols.

03 — Compiler Magic Constants

Compilers replace % N with a multiply-and-shift sequence using a precomputed magic constant. Recognizing 92492493h (÷7) and 66666667h (÷5) lets you instantly decode modulo constraints without tracing the full arithmetic.

04 — Subtraction Reveals Type

sub eax, 41h means the code expects a letter (subtracting 'A'). sub eax, 30h means digit (subtracting '0'). cmp al, 2Dh means literal dash. These patterns decode character type expectations at a glance.

05 — Absence Is Information

key[3] had no stack variable and no arithmetic — IDA didn't name it. The absence of a transform meant the position was unconstrained. Noticing what the code doesn't do is as important as what it does.

06 — Model Then Brute

Reversing the math before writing any code is critical. The keygen isn't a random guesser — it only iterates over the constrained search space (a, b, c) and applies the exact mathematical conditions extracted from the binary. Modelling first, implementing second.

✓ Core Takeaway

Reverse engineering is pattern recognition. Every IDA session adds shapes to a mental library — compiler idioms, optimization patterns, character encoding tricks. This challenge built the foundation for reading real-world binaries: license checks, authentication routines, and custom protocol parsers all reduce to the same process.
