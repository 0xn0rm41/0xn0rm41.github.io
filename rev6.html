Recognizing Common Algorithms

Identifying CRC32, RC4, and FNV-1a from raw disassembly — no source code, no runtime, no search engine.

Overview

Malware encrypts C2 traffic, hashes API names, and checksums payloads using standard algorithms embedded directly in the binary. An analyst who recognizes the disassembly signature of CRC32, RC4, or FNV-1a instantly moves an order of magnitude faster than one who reverses every instruction from scratch.

Three anonymous functions — algo_a, algo_b, algo_c — were identified purely from their disassembly structure and magic constants, without source code, runtime execution, or external references.

algo_a — Identified: CRC32

CRC32
Cyclic Redundancy Check — 32-bit
0xFFFFFFFF
initial value and final XOR mask — CRC32 standard init/finalize
0xEDB88320
reversed CRC32 polynomial — the single strongest fingerprint
8 inner iters
one bit processed per iteration — bit-by-bit CRC implementation
Used in malware for payload integrity checks, config verification, and string hashing for obfuscated API resolution. 0xEDB88320 is the most recognizable constant in binary analysis — confirmed on sight.
IDA — CRC32 inner loop
; outer: one byte per iteration
movzx   edx, byte ptr [esi]
xor     eax, edx              ; crc ^= data[i]
mov     ecx, 8                ; 8 inner iterations — one per bit

loc_inner:
mov     edx, eax
shr     edx, 1
xor     edx, 0EDB88320h       ; ← CRC32 polynomial fingerprint
mov     ebx, eax
shr     ebx, 1
test    al, 1
mov     eax, edx
cmovz   eax, ebx              ; conditional XOR poly or just shift
sub     ecx, 1
jnz     short loc_inner

algo_b — Identified: RC4 KSA

RC4 KSA
Rivest Cipher 4 — Key Scheduling Algorithm
256 iterations
first loop — S[i] = i for all 256 entries
cmp eax, 100h
boundary check — 0x100 = 256, the S-box size
swap pattern
second loop — key-dependent byte swaps across S-box
RC4 is the most common stream cipher in malware — C2 traffic encryption, payload decryption, config obfuscation. Finding the KSA means the encryption key is the argument — read it from the register at the call site in GDB.
IDA — RC4 KSA
; Loop 1 — S-box init
mov     [ebp+eax+0], al       ; S[i] = i
add     eax, 1
cmp     eax, 100h            ; ← 256 iterations
jnz     short loc_init

; Loop 2 — key-dependent swap
movzx   ecx, byte ptr [ebp+ebx+0]
; ... j = (j + S[i] + key[i % keylen]) % 256 ...
movzx   edx, byte ptr [eax]
mov     [ebp+ebx+0], dl       ; S[i] = S[j]  ← swap
mov     [eax], cl             ; S[j] = tmp   ← swap
add     ebx, 1
cmp     ebx, 100h            ; ← 256 iterations again
jnz     short loc_ksa

algo_c — Identified: FNV-1a

FNV-1a
Fowler–Noll–Vo Hash — 32-bit variant 1a
0x01000193
FNV prime — the definitive constant for this algorithm
0x811c9dc5
FNV offset basis — initial hash value
XOR then IMUL
FNV-1a operation order — XOR first, multiply second
FNV-1a is dominant in malware for obfuscated API resolution — instead of storing "CreateThread" as a detectable string, malware stores its FNV-1a hash and compares against hashed export names at runtime. Seeing imul eax, 1000193h near PE export table traversal is a near-certain indicator of this technique.
IDA — FNV-1a loop body
; two instructions — complete inner loop
xor     eax, ecx             ; h ^= byte         ← XOR first (FNV-1a)
imul    eax, 1000193h        ; h *= FNV_PRIME     ← multiply second

; FNV-1 = multiply then XOR — FNV-1a = XOR then multiply
⚡ FNV-1 vs FNV-1a

Same constant, opposite operation order. XOR-then-multiply = FNV-1a. Multiply-then-XOR = FNV-1. Malware almost universally uses FNV-1a for better avalanche properties.

What I Learned

01 — Constants Are Signatures

0xEDB88320 appears in exactly one algorithm. A single constant match is sufficient for identification — no surrounding context required once the library is built.

02 — Loop Bounds Identify Structures

cmp eax, 100h in two consecutive loops with swaps in the second is RC4 KSA. The 256-byte S-box size is architectural — it cannot be anything else.

03 — Operation Order Distinguishes Variants

FNV-1 and FNV-1a share the same constant but differ in operation order. XOR-then-multiply is FNV-1a. Two instructions, opposite order — different algorithm.

04 — RC4 KSA Exposes the Key

The KSA is always followed by the PRGA encryption loop. Finding the KSA means the encryption key is an argument to this function — readable directly from the register at the call site in GDB.

05 — FNV-1a Signals API Obfuscation

When FNV-1a appears near PE export table traversal, the binary resolves API names by hash at runtime. The hashed names are recoverable by hashing all known Windows API names offline.

06 — The Library Compounds

Eight constants recognized across six modules. After twenty real samples the library covers most common algorithms and anti-analysis primitives. Speed comes from accumulated recognition, not faster reading.
