Overview

Static analysis reveals what a binary can do. Dynamic analysis reveals what it actually does at runtime — including behavior that no amount of disassembly reading would expose quickly, such as the plaintext value of an obfuscated key recovered directly from a register at the point of use.

The target binary simulates a realistic malware dropper: it performs sandbox evasion via PID check, drops a C2 configuration file to disk, and gates its unlock path behind an environment variable key. Three analysis passes — ltrace, strace, and GDB — were used in sequence to map the complete behavior.

Tool Overview

ltrace
Library call interception

Intercepts every libc call with arguments and return values. Ideal for spotting file operations, string comparisons, environment reads, and crypto calls without touching a disassembler.

strace
Syscall interception

Intercepts every kernel syscall — file open/write, network, process creation, memory mapping. The ground truth of what a binary does to the OS, one level below ltrace.

GDB
Full runtime control

Breakpoints, register inspection, memory reads at arbitrary points. The final stage — zoom into a specific function, read return values directly off registers, bypass checks in real time.

Pass 1 — ltrace: Library Call Snapshot

ltrace ./behavior AAAA 2>&1 | head -30

getpid() = 12483
fopen("/tmp/.hidden_cfg", "w") = 0x...
fputs("c2=192.168.1.1\nport=4444\n", 0x...) = 28
fclose(0x...) = 0
chmod("/tmp/.hidden_cfg", 0600) = 0
getenv("UNLOCK_KEY") = nil
puts("[-] Locked.") = 13

The entire behavioral profile surfaces in a single ltrace pass — no disassembly required. Three distinct behaviors are immediately visible: a PID-based sandbox check, a file drop with C2 configuration, and an environment-variable-gated unlock path. getenv("UNLOCK_KEY") = nil confirms the key wasn't set — the strcmp never fires because validate() exits early on a NULL check.

Pass 2 — strace: Syscall Layer

strace ./behavior AAAA 2>&1 | grep -E "open|write|chmod|getpid"

getpid() = 12483
openat(AT_FDCWD, "/tmp/.hidden_cfg", O_WRONLY|O_CREAT|O_TRUNC, 0666) = 3
write(3, "c2=192.168.1.1\nport=4444\n", 25) = 25
chmod("/tmp/.hidden_cfg", 0600) = 0

strace confirms the file write at syscall level and adds detail ltrace omits: the file is opened with O_CREAT|O_TRUNC — created fresh each run, overwriting any existing config. chmod 0600 restricts access to owner read/write only — deliberate operational security, preventing other processes from reading the C2 configuration.

⚡ chmod 0600 — Intentional OPSEC

Legitimate software rarely chmods config files to 0600 immediately after writing. In malware this is standard — the implant doesn't want other processes, log collectors, or EDR agents reading its configuration off disk.

Behavioral Findings

Sandbox Evasion — PID Check
Evasion
getpid() is called at entry. If the returned PID is below 10, the process exits immediately. Automated sandboxes sometimes assign very low PIDs to isolated processes — this is a cheap heuristic to detect and exit before behavioral analysis begins. Bypass: set $eax = 1000 in GDB after getpid returns, before the comparison fires.
C2 Config Drop — /tmp/.hidden_cfg
Malicious
Binary writes a plaintext configuration file on every execution containing C2 address (192.168.1.1) and port (4444). File is created at /tmp/.hidden_cfg — hidden by leading dot, low-visibility location. Permissions set to 0600 immediately after write. Classic dropper behavior: config written to disk for persistence across sessions.
Environment-Keyed Unlock
Key Gating
validate() reads UNLOCK_KEY from the environment and compares it to the user-supplied argument via strcmp. Key is not hardcoded in the binary — passed at runtime via environment variable. This pattern appears in staged implants where the operator supplies the activation key out-of-band, making static analysis of the binary alone insufficient to activate the payload.

Pass 3 — GDB: Register-Level Key Extraction

With UNLOCK_KEY=secret set, a breakpoint on validate() captures the exact moment getenv returns. The plaintext key value is visible directly in $eax — no decryption, no tracing of derivation logic required.

set environment UNLOCK_KEY = secret
break validate
run secret

Breakpoint hit: 0x080492a8 in validate()

⚡ The Core Dynamic Analysis Principle

The CPU cannot execute obfuscated data — it must resolve everything to plaintext before use. A breakpoint at the point of use always hands you the real value, regardless of how many layers of XOR, RC4, or custom derivation preceded it. EAX = 'secret' the instant getenv returns — no static analysis of the key derivation was necessary.

What I Learned

01 — ltrace Before IDA

A single ltrace pass surfaces file drops, env reads, string comparisons, and crypto calls in seconds. It answers "what does this binary do?" before a disassembler is opened — directing where to focus static analysis.

02 — strace Is Ground Truth

strace operates one level below ltrace — at the syscall boundary. It cannot be fooled by library-level hooks or LD_PRELOAD tricks. For file, network, and process behavior it is the definitive record.

03 — The CPU Resolves Everything

No matter how obfuscated the key derivation, environment read, or config decryption — the CPU must produce plaintext before use. A breakpoint at the right moment reads the answer directly from $eax.

04 — Early Return Hides Calls

getenv = nil caused strcmp to never appear in ltrace output. Understanding early-return patterns prevents false conclusions — absence of a call in trace output doesn't mean it doesn't exist in the binary.

05 — PID Checks Are Cheap Evasion

Checking getpid() < 10 is a one-line sandbox evasion primitive. Real malware uses timing checks, CPUID, registry keys, and mouse movement detection — all variants of the same pattern: detect analysis environment, exit cleanly.

06 — File Permissions Signal Intent

chmod 0600 immediately after writing a config file is not normal software behavior — it's deliberate operational security. Unusual permission changes on newly written files are a behavioral IOC in their own right.
